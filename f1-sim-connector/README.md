# f1-sim-connector

**Case 7 — Edge connector for live game telemetry.** The platform's equivalent of a
*PI Interface / PI Connector*: it receives the F1 game's UDP telemetry from a PS5 on the LAN
and feeds the **`box-box`** historian with a live 60 Hz stream — the one data class that
public F1 data never offers, with a *known* car setup.

> Status: scaffold — header parser, tag scheme, edge exception filter and store-and-forward
> buffer with unit tests. UDP listener, packet bodies and the historian client land next.

## What it does

| Concern | Implementation |
|---|---|
| Protocol | versioned parser for the game's UDP packets (`protocol.py`); unknown formats are rejected, never guessed |
| Tags | `SIM.CAR{idx}.SPEED`, `SIM.CAR{idx}.TYRE.FL.TEMP`, … (`tags.py`) |
| Edge compression | exception deviation per tag before anything leaves the edge (`compression.py`) |
| Resilience | store-and-forward buffer: nothing is lost while the historian is down (`buffer.py`) |
| Trust | every sample carries a quality: good / bad / stale / substituted (`quality.py`) |

The motion rig does **not** go through this connector or the historian; it reads the UDP
stream directly because latency matters. See `FOUNDATIONS.md`.

## Run

```bash
docker compose up sim-connector            # listens on udp/20777
uv sync && uv run f1-sim info
uv run pytest
```

Environment: `SIM_UDP_PORT` (default `20777`), `SIM_BOXBOX_URL` (default `http://localhost:8081`).
Enable UDP telemetry in the game's settings and point it at the host running the connector.
